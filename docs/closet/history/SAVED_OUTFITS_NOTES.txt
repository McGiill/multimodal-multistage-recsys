2026-11-20 코디 저장 기능

사용 방법
- 코디 창 또는 기존 코디 상세에서 '♡ 코디 저장'을 누릅니다.
- 마이페이지 상단 '저장한 코디'를 누르면 저장 목록으로 이동합니다.
- 저장한 사진을 누르면 코디와 유사상품을 다시 볼 수 있습니다.
- '♥ 저장됨'을 다시 누르면 저장을 취소합니다. 코디 창과 목록 양쪽에서 가능합니다.
- 동일 회원/동일 코디는 한 번만 보관합니다. 서로 다른 상품에서 같은 코디를 저장하면
  사진은 중복되지 않고 마지막으로 지정한 상품 연결을 사용합니다.
- 새로고침/서버 재실행 후에도 같은 --state-dir의 DB를 사용하면 유지됩니다.
- 성별·추천 범위가 바뀌면 맞지 않는 저장 코디는 숨기고 기록은 유지합니다.
- 원래 옷을 옷장에서 빼도 저장한 코디는 유지됩니다.

API
GET /api/closet/saved-outfits?user_id=<id>
  outfits: 현재 범위에 유효한 저장 코디(최초 저장 시각 내림차순)
  항목: id, outfit_id, product_id, saved_at, image, title, product, saved
  total_count: 숨겨진 항목까지 포함한 전체 저장 수
  hidden_count: 현재 성별/검수/상품연결 조건에서 숨긴 수
POST /api/closet/saved-outfits?user_id=<id>
  {"outfit_id":"musinsa_...", "product_id":"hm_...", "saved":true}
  취소는 saved:false. 삭제된 옛 연결도 ID로 취소 가능.
  존재하는 검수 연결과 현재 성별·의류 범위를 확인한 후 저장합니다.
  결과: {"outfit_id":"...", "saved":true/false}
GET /api/closet/outfit 응답에 saved:boolean 추가.

저장 구조
- 기존 profiles.sqlite3에 saved_outfits 테이블을 자동 생성합니다.
- 기본키(user_id, outfit_id), product_id, saved_at을 저장합니다.
- 다시 저장 요청해도 중복/저장시각 누적 없음. 회원별 데이터 분리.
- 구매/상품조회/보유이력 또는 취향조사 seed로 자동 변환하지 않습니다.
- 코디를 실제로 열면 기존 outfit_view 기록은 계속 남습니다.
- 저장 신호의 Two-Tower 반영은 이번 범위에 포함하지 않습니다.
- 로컬 시연용 사용자 ID를 사용하며 실제 서비스 인증을 추가한 기능은 아닙니다.

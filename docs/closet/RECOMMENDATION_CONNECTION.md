# 코디 선택을 기존 상품 추천에 연결 — 2026-11-22

별도 상품 추천 화면을 만들지 않는다. 기존 `/api/recommend` 목록에 현재 선택·저장 코디의 연결 상품을 별도 취향 신호로 반영한다. 조회·장바구니·구매 이벤트, 세션 클릭, 모델의 행동 이력은 생성하거나 수정하지 않는다.

## 동작

1. 기존 쇼핑몰과 옷장 데모의 상품 추천 요청에 `use_outfit_preferences=true`를 보낸다.
2. 팀 API가 같은 `user_id`로 옷장 `/api/closet/preference-seed`의 최신 스냅샷을 읽는다. 선택·저장 상태는 기존 옷장 SQLite에 저장하며 별도의 누적 이벤트를 만들지 않는다.
3. 추천 모델 카탈로그에 정확히 같은 ID가 있고 추천 시점에 등록된 상품만 최대 32개 보탠다. 빠진 ID를 임의 매핑하지 않는다.
4. 기존 모델로 후보 점수를 계산한 뒤 최종 정렬에 관심 가점을 적용한다. 신규 사용자의 인기·트렌딩 목록에도 이 단계를 적용하므로 선택 정보가 사라지지 않는다. 신규 사용자 판정은 실제 이력 그대로다.
5. 카테고리 다양성·동일 디자인 중복 제거·신상품·MAB 탐색 규칙을 이어서 적용한다. 영향을 준 일반 상품에는 `reason=outfit_preference`를 표시한다. 탐색/신상품 칸은 기존 사유가 우선이다.

현재 방식은 **연결 상품에 대한 별도 정렬 규칙**이다. 사용자 벡터 수정·추가 학습·유사한 전체 상품으로의 벡터 확장은 하지 않는다. 기존 `preferences/adapter.py`의 64D 벡터 결합은 이번 경로에 사용하지 않는다.

정렬 키는 `(1-a)/(기존 순위+1) + a × (상품 상대가중치/최대 상대가중치)`이다. 기존 목록에 없던 연결 상품의 첫 항은 0이다. `a = max_weight × 남은 신호 비율 / (1 + 실제 이력 슬롯 수/history_decay)`이며 현재 실험 기본값은 0.2와 5다. 점수는 출력용 구매 확률로 바꾸지 않고 후보의 원래 score를 유지한다. 따라서 반환 score 내림차순과 최종 순서가 다를 수 있다. **조회 1회보다 몇 배 강하다는 뜻이나 품질 검증된 계수가 아니다.**

## 실행과 확인

- 옷장: 기존 최신 `closet-demo-60.zip`으로 `python -m src.closet.run --data-root "../closet-demo-data-60"` (8767).
- 팀 추천 API: 기존 학습 모델·데이터를 준비한 환경에서 `uvicorn src.serving.main:app --port 8000`.
- 두 화면은 **같은 user_id**를 사용해야 한다. 로그인/회원 인증 통합은 이번 변경 범위 밖이다.
- 요청 예: `/api/recommend?user_id=U00005&top_n=10&use_outfit_preferences=true`.
- 시뮬레이터 기준 시각이 필요하면 기존처럼 `at`을 지정한다. 현재 선택을 쓰는 시연이며 과거 시점 평가 결과로 해석하면 안 된다.
- 기본 API 요청/오프라인 평가는 옵션을 켜지 않으므로 기존 결과와 평가 분할을 유지한다. 다른 추천 전략에 옵션을 보내면 400을 반환한다.
- `X-Outfit-Preference-Source` 헤더: `loaded`/`empty`/`unavailable`/`disabled`. `loaded`는 취향 원본 조회 성공이며 모델 카탈로그 매칭이나 품질 개선 보장이 아니다.
- 설정: `configs/outfit_preferences.yaml`. `enabled: false` 또는 요청 옵션 false로 비활성화. 주소는 `CLOSET_PREFERENCE_URL` 환경변수로 변경할 수 있다.
- Docker Desktop 팀 API는 호스트 옷장에 접근하도록 `docker-compose.yml`에 `host.docker.internal:8767` 기본 주소를 넣었다. 포트가 다르거나 Linux 환경이면 접근 가능한 주소를 별도로 설정한다.
- 조회 지연(실패 포함)도 추천 API latency에 포함한다. 제한 시간은 기본 150ms이며 실제 전체 응답시간은 모델 환경에서 별도 측정해야 한다.

## 변경·취소·장애

- 매 요청마다 현재 상태를 읽고 이전 취향을 캐시하거나 더하지 않는다. 선택 변경은 교체, 마지막 신호 삭제는 기존 추천으로 복원된다.
- 저장 취소는 저장 신호만 제거한다. 같은 코디가 조사에 남아 있으면 그 선택은 유지된다.
- 조사 창의 건너뛰기/닫기는 종전 선택을 유지한다. 사진을 모두 해제하고 완료하면 `POST /api/closet/survey`의 `{"selected":[],"skipped":false,"clear":true}`로 조사 선택만 비운다. 저장 목록과 실제 조회 이력은 유지한다.
- 원본 API 중단·타임아웃·잘못된 사용자 응답은 기존 추천으로 복귀한다. 오래된 선택을 대신 쓰지 않는다.
- 모델이 없으면 추천 API는 기존처럼 503을 반환한다. 테스트용 점수나 임의 상품을 실제 추천으로 대신 내보내지 않는다.
